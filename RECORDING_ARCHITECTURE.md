# Recording architecture (stage 3 in progress)

`StreamRecorder` is the domain boundary. `ProgressiveStreamRecorder` rechecks the latest source record and `ContentCapabilityResolver` immediately before opening a connection. Only verified hosts with explicit `canRecord` and progressive MP3/AAC over HTTPS pass the gate. HLS, unknown hosts, disabled sources and unverified rights cannot be recorded. All current production stations have recording disabled, so there is no recording action in the UI.

When authorized, the recorder rechecks rights for the final host after redirects, then streams OkHttp response bytes into an app-managed `files/recordings/*.part` file using bounded memory. For catalog radios without a declared format it validates the GET response's Content-Type, then checks the MP3/ADTS header and chooses the matching extension. It supports a free session and 5/10/15/30-minute durations, low-storage checks, cancellation, final rename and Room metadata. HLS recording is unsupported because playlists, discontinuities, encryption and container conversion need separate handling. Playback and recorder use independent network connections; changing the playback station does not change the recording target.

User initiated recording runs under a `dataSync` foreground service with a persistent notification and Stop action. A free session is capped at five hours to respect Android's finite foreground time budget. Old `.part` files are removed after 24 hours on the next recorder initialization. Output must pass minimum size and MP3/ADTS header checks; complete decoder validation and device integration tests remain open. The recording action appears only if current capabilities explicitly allow it; current production sources do not. The files remain local; no recording is uploaded to Supabase.
